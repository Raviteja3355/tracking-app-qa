## 36. Error Boundary 分层防护 `d2836c5`

官网核心防崩策略，3 层 boundary 隔离不同影响半径：

**Layer 1 — 营销工具（静默，`fallback={null}`）**
- `SharedLayout.tsx`：Analytics、Clarity、Intercom、CookieBanner 各自独立包裹
- 任一崩溃不影响主功能，用户无感知

**Layer 2 — 单张 ParcelCard（降级空壳）**
- `TrackingResults.tsx`：每张卡片用独立 `<ErrorBoundary>` 包裹
- 崩溃的卡片显示 `tracking number | Failed to load`，其余卡片正常渲染

**Layer 3 — TrackingResults 整区（引导重试）**
- `TrackingHero.tsx`：整个 Results 区包裹
- 崩溃时显示 "Something went wrong + Try again"，Header 和 TrackingInput 保持可用

**页面级 Section Boundary**
- `app/(en)/page.tsx` / `app/(fr)/fr/suivi/page.tsx`：
  - FAQ → `fallback={null}`（静态内容，静默降级）
  - CustomerSupport → `fallback={<SupportUnavailable />}`（引导用户使用 Intercom chat）

**新增文件**
- `components/ui/ErrorBoundary.tsx`：通用 class 组件，支持 `fallback={null | ReactNode | (reset) => ReactNode}`
- `components/ui/ThrowError.tsx`：dev 工具，用于手动触发 boundary 测试
